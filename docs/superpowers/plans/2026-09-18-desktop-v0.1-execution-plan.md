- 不新增无当前消费者的 `Manager`、`Repository`、`Factory`、`Event Bus`、数据库、插件运行时、通用审批框架、通用任务队列或自动重试机制。这些名称不构成设计收益。
- 不因单一调用方或测试替身需要而增加接口层。新增字段必须指出写入方、生产读取方以及删除后实际丢失的行为。
- 不修改无关模块，不进行全仓格式化、目录重排、统一命名或顺手重构。文件长度不是拆分依据。
- 同一业务事实只有一个权威来源。界面、持久化与诊断可以有明确投影，但不能各自推断另一套产物成功或步骤完成规则。
- 信任同进程静态类型；仅在文件、用户输入、进程、模型、网络等真实边界校验本阶段消费的字段。
- 程序错误直接暴露。不得通过空数组、默认成功、吞异常或自动跳过失败使验收变绿。
- 会话的删除和重命名是宿主管理操作；它们不授权改写保留会话的历史，也不授权删除源视频或生成文件。
- `0.x` 允许修正内部接口，不等于允许清空已有用户文件或会话。受影响的现存持久化格式必须有明确处理；只做实际需要的读取映射，不搭建迁移框架。
- 新依赖须说明当前问题、现有能力为何不足和引入范围。复用标准库及已有依赖；不为理论兼容扩大依赖面。
- 核心注释按仓库规范使用中文，解释复杂语法与职责原因。文档中的概念说明使用固定三列 `text` 代码块，不用概念表格或堆叠中英对照。

### Commit 33 / P0：关闭时保存收尾

- **目标**：正常关闭窗口时完成会话落盘；运行中关闭时先取消当前任务并等待必要收尾，不静默丢失已完成事实。
- **必要性**：当前客户端在非处理中延迟 150ms 请求保存，桌面窗口关闭没有与该保存协议衔接。
- **前置依赖**：30–32 已验收，已有取消信号与会话持久化。
- **主要影响模块**：`apps/desktop/src/main/index.ts`、`session-persistence.ts`、`packages/client/src/App.tsx`；确需通信时同步 `api.ts`、preload 与 IPC 调用方。
- **明确不做**：断点续跑、进程崩溃恢复承诺、后台任务、数据库、通用保存队列和复杂状态机。

实施顺序：先覆盖正常关闭前保存未落盘与运行中关闭两个现有入口；复用当前取消信号和保存函数，确保完成或取消后的可持久化状态已就绪再关闭。不要把 `processing` 快照强行改成成功，也不要放宽磁盘解析来接受临时流式文本。保存失败必须可见，不能声称已保存后退出。

- **目标**：视频工具遇到已有用户输出文件时明确失败，保持该文件内容不变。
- **必要性**：当前多个 FFmpeg 调用使用 `-y`，模型提供的目标路径可能指向已有文件。
- **前置依赖**：现有视频工具与真实 FFmpeg 环境。
- **主要影响模块**：`packages/video-ffmpeg/src/index.ts`、`tests/video-ffmpeg.test.ts`；仅在命名确有冲突时调整桌面输出命名调用方。
- **明确不做**：每次调用审批、授权策略系统、自动改名重试、互斥锁、事务和覆盖后的回滚。

实施顺序：列出实际可写用户文件的命令入口，包括抽帧的具体文件；在真正写入的 FFmpeg 边界选择拒绝覆盖的执行方式，优先使用现有程序支持的 `-n` 等参数。不能仅在界面检查后继续用 `-y`。工具私有临时目录与持久用户输出分别按真实用途处理，不为机械替换而改动无关临时文件逻辑。冲突作为真实工具错误交回模型，由模型判断后续动作。

### Commit 35 / P0：成功产物的唯一识别

## 8. 验证命令与执行边界

按当前根脚本运行，不能自行拼出一套遗漏架构或测试类型检查的替代门禁：

```powershell
corepack pnpm install --frozen-lockfile
corepack pnpm check
```

修改界面、宿主接口或构建时追加：

```powershell
corepack pnpm desktop:build
```

涉及共享界面交互时复用浏览器测试：

```powershell
corepack pnpm client:web:test
```

真实开发窗口验收与生产构建入口分别为：

```powershell
corepack pnpm desktop:dev
corepack pnpm desktop
```

以上启动命令按验证目的择一运行，不同时无意义启动多个应用。先检查现有服务所属项目和端口；不结束他人服务，不直接启动裸 `electron.exe`。安装产物验收启动43生成的实际应用，不以开发窗口替代。

聚焦现有测试的命令示例，按阶段选择实际文件：

```powershell
corepack pnpm exec vitest run apps/desktop/tests/main-entry.test.ts apps/desktop/tests/session-persistence.test.ts
corepack pnpm exec vitest run packages/video-ffmpeg/tests/video-ffmpeg.test.ts
corepack pnpm exec vitest run apps/desktop/tests/agent-task.test.ts packages/client/tests/app.test.tsx
```

聚焦通过后仍执行项目要求的 `pnpm check`。不要为每阶段另建配置、验证服务器或测试框架。编写时存在的 `*.verify.config.ts` 属于30–32工作区内容，不能仅凭文件名把它们升级为新权威门禁。

变更外部模型、FFmpeg、Whisper 或 Vision 实际行为时，按工程规范执行对应真实链路。缺凭据时不得打印或搜索泄漏秘密；明确缺少的是哪个条件。`pnpm check`、`git diff --check` 或网页模拟成功都不能替代真实外部验收。

## 9. 最终真实入口验收矩阵

只使用专门的测试素材、输出目录和隔离的测试用户数据，不覆盖用户现有媒体。每项记录输入、实际组件、观察到的结果、输出或截图位置与状态；不预填测试数量和成功结论。

1. 首次启动：无已保存密钥仍能进入应用与设置；配置后真实文字任务可完成。
2. 固定区间剪辑：真实模型与 FFmpeg 完成指定时间段输出；检查时长并观看内容。
3. 语义剪辑：真实 Whisper 时间轴与模型判断完成既有语义流程；检查片段内容，不能仅检查文件存在。
4. 视觉理解：发布承诺该能力时，用真实 Vision 调用核对必要画面观察；未执行不能宣称通过。
5. 多轮与多会话：上下文、草稿、附件和产物各自归属正确；主窗口仍只允许一个活动任务。
6. 取消与部分产物：真实长工具执行可取消，已成功文件保留，后续发送可用；不残留本次子进程。
7. 真实失败：不可用输入或执行条件能显示真实失败与可定位诊断，不能伪造成功产物。
8. 覆盖冲突：已有输出内容保持不变，工具明确拒绝覆盖；不会等待不可见的命令行输入。
9. 音频与字幕：纳入版本时分别执行真实音轨替换与 SRT 烧录，观看或听取结果。
10. 正常关闭与恢复：立即关闭、运行中关闭和重启后历史符合33的约定，不改写原会话事实。
11. 搜索：匹配标题或正文后进入正确会话，草稿、附件和输入焦点符合既有交互。
12. 安装环境：离开源码仓库启动，日志与数据可写，缺少外部依赖有明确解释，最终安装包与验收记录一致。

视觉验收按 `docs/desktop-ui.md` 的当前矩阵，覆盖接近默认桌面和窄窗口、长路径、展开活动、失败与取消。必须观察真实渲染；有截图则记录路径。截图工具失败时保留正确应用并说明人工观察范围，没有观察证据的项目不能标为通过。不得修改产品代码迎合截图工具。
