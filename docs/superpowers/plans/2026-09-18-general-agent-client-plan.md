### 1.1 交付纪律

1. 只要求读方案时，只读；要求执行指定阶段时，仅执行该阶段及其必要接手检查。
2. 后续用户只说“执行本方案”而没有指定连续范围时，先执行第 2 节，再完成第一个尚未满足的 P0 阶段并交付。不得默认连续做到 50。
3. 用户明确授权连续范围时，按范围推进，不重复询问已授权的常规实现选择。Git 操作仍按已有授权执行，不把阶段编号当作操作授权。
4. 一个阶段只解决一个明确问题。每阶段需要可独立审查、验证和回退；不得把全部阶段放在一个长期分支最后一次合并。
5. 没有提交授权时，阶段验收后交付未提交差异并停止继续累积。已有未提交工作不能通过强制重置、清理文件或选择性还原来“整理”。
6. 依赖阶段通过审查和必要验收、并完成已授权的集成后，再从更新后的基线开始下一阶段。不要为未开发阶段提前创建分支或工作树。
7. 存在同一调用链的并行修改时，明确当前修改负责人。不能在他人持续修改的文件上补另一半契约；不接管或终止其他 AI 的任务。
8. 已有实现满足目标时，验证后标记“已满足”；不重复开发，不为编号连续制造提交。

### 4.2 通用任务行为

- 普通问答直接回答；纯数字或含义不清的短句只做简短澄清，不机械列出全部视频功能。
- 路径、文件类型、时长、文件数量等可检查事实由工具获取。成片长度、剪辑风格等用户偏好只在影响下一步时询问。
- 没有最终输出路径不阻止读取、搜索或媒体探测。写出前再确定目标路径，并继续遵守不静默覆盖规则。
- “最后一个工具写入最终文件”等现有媒体规则仅适用于实际写出任务；普通问答、读取和搜索不为了满足规则额外生成文件。
- 通用规则和视频规则在现有系统指令边界集中维护。Desktop 只传入真实附件、工作目录和当前能力等事实，不在用户消息尾部追加“一律禁止工具”的策略。
- 按实际注册能力描述可用操作。没有语音或视觉工具时直接说明缺少什么，不能假装已经理解剧情。
- 不要求模型公开完整内部推理；进度和简短决策说明以实际操作和工具结果为依据。
- 基础阶段不新增“聊天模式/视频模式/通用模式”等切换器。工具可见性由真实配置和权限决定。

### 4.3 路径与目录接入

1. 视频附件继续可用；会话工作目录是独立字段，不由最后一次附件选择暗中覆盖。
2. 目录选择器确认的目录成为当前会话工作目录。绝对路径文字由模型传给 `set_working_directory` 工具，不在 Renderer 用正则解析自然语言。
3. `set_working_directory` 校验目录存在，再由宿主展示一次明确的目录访问确认；批准后同一 Turn 的后续工具即可使用新目录。已经确认的同一目录不重复审批；换到新目录重新确认。
4. 会话只保留一个当前工作目录；不建设多项目库、目录收藏或复杂工作区实体。相对路径以该目录为基准；没有基准时返回明确错误，不猜用户主目录或应用安装目录。
5. 一个 Turn 中工具读取该会话同一份目录状态，不能各自缓存旧路径。目录变化作为工具结果进入 Session；宿主保存当前选择，恢复后两者职责不混淆。
6. 新增本地文件工具的读取范围为已确认目录及其子目录、明确选择的文件。工具边界处理绝对路径、`..`、符号链接和 Windows 目录联接；不能用字符串前缀代替实际路径范围判断。越界返回具体错误或进入实际需要的目录授权，不能悄悄扩大范围。
7. 不把目录选择称为操作系统沙箱；尤其通用 PowerShell 可以访问进程权限内的其他资源，44 必须按完整命令授权。

### 4.4 审批的最小实现

审批在 38 随“使用指定目录”这一真实消费者落地。42、43、44 复用同一通道，逐项增加实际操作，禁止先建设没有使用者的审批平台。

- Main 持有一个当前待决请求；绑定会话、当前轮次的取消信号、请求标识和准确操作参数。模型不能把自己的文本当作批准。
- Shared Client 显示具体目录、文件变更或命令，提交允许或拒绝。IPC 只接受当前请求的决定，不允许客户端用回复修改待执行路径或命令。
- 工具等待宿主注入的审批回调，结果回到原调用；不依赖 React 或 Electron。注册表与循环不增加桌面审批逻辑。
- 取消、关闭、请求失效和宿主销毁必须结束等待；批准已失效请求不能重新启动操作。取消语义继续走既有 AbortSignal，不伪装为普通工具失败。
- 拒绝后返回可见的未执行结果，不能换工具或改写命令绕过拒绝。一次性批准不自动变成永久命令白名单。
- 不新增通用规则语言、风险评分器、自动批准模型或审批数据库。

### 4.5 命令、输出与产物

- 44 的首版是单个前台 PowerShell 命令。明确 `command`、`workdir`、输出上限和执行超时，捕获标准输出、错误输出、退出码；超时与用户取消有不同结果。
- 每次进程使用明确工作目录，不依赖上一条命令的 `cd` 或变量。不要在渲染进程执行，不创建持久终端、后台任务服务或多命令队列。
- 批准后仍使用同一个取消信号。Windows 上必须实际验证命令及子进程终止，不能只让 UI 显示取消。
- 默认每条通用命令展示并审批；不用关键字黑名单或“看上去只读”把任意 PowerShell 宣称为安全命令。不实现操作系统级沙箱时，应在权限说明中如实描述执行范围。
- 各文件/搜索/命令工具在产生结果时限制输出量，并报告截断及继续读取方法；不能等到模型上下文已经溢出才处理。

- 编辑已有文件展示为文件变更，不冒充新生成产物。任意命令退出码为 0 不代表生成了某文件；首版命令不自动登记产物，不扫描磁盘猜测文件归属。
- 失败或取消前已经成功的工具产物仍归属原轮次，不删除、不丢失；失败调用自己的半成品不能标为成功。

- REMOVE：无调用方的接口、预留配置、空包、空菜单、为未来编号建立的适配器，以及通过关键词强制剪辑流程的 UI 逻辑。

## 7. 验证与真实入口门禁

### 7.1 每阶段执行顺序

- [ ] 先列出本阶段目标、当前缺口、实际调用方、允许修改的文件和不做的内容。
- [ ] 以能观察行为的测试复现关键问题。测试聚焦结果、权限拒绝后的无副作用、取消和历史保留，不镜像内部方法或凑覆盖率。
- [ ] 实施一个完整的最小调用链；契约修改同步更新生产调用方、快照解析、Web 模拟与直接测试。
- [ ] 运行聚焦验证，失败时先解释原因再修复；不删掉失败场景、忽略丢失字段或放宽断言换取 PASS。
- [ ] 按当前 `docs/engineering.md` 完成统一门禁与实际差异审查。
- [ ] 执行该阶段需要的真实模型、文件、进程或 GUI 验收；记录实际证据和未验证范围。
- [ ] 对最终差异完成审查、交付；得到已有授权范围内的集成结果后再开始下一阶段。

当前可以使用的命令如下。依赖安装依据仓库工程流程执行，不升级依赖；本方案编写不执行这些功能门禁。

```powershell
pnpm install --frozen-lockfile
pnpm check
pnpm desktop:build
pnpm client:web:test
pnpm desktop
git diff --check
```

开发中可按实际变更选择以下聚焦测试；新包尚未建立时不要运行不存在的测试路径：

```powershell
pnpm exec vitest run apps/desktop/tests/agent-task.test.ts apps/desktop/tests/session-persistence.test.ts
pnpm exec vitest run packages/video-agent/tests/video-agent.test.ts
pnpm exec vitest run packages/local-tools/tests
pnpm exec vitest run packages/client/tests/app.test.tsx apps/desktop/tests/main-entry.test.ts
```

`pnpm check` 通过不等于真实模型正确选工具，也不等于桌面界面可用。修改提示词和工具可见性必须使用真实模型验证任务行为；修改共享界面要跑相关浏览器验证，并在真实 Desktop 检查宿主集成。

### 7.2 发布前必须覆盖的任务

1. 无附件输入普通问题和纯数字：正常回答或短澄清，不重复整个视频参数清单。
2. 新会话输入一个真实目录和“这里的 MP4 做影视切片”：模型调用目录工具，经必要的一次目录确认后找到文件；不要求用户手工报文件数量和名称。
3. 在具备所需语音/视觉依赖的环境完成真实内容剪辑：检查素材、确定区间、生成新文件、显示真实产物。功能缺失时明确说明缺少的能力，不能假装完成。
4. 指定目录中查找字幕台词：使用发现、读取和搜索工具返回文件及行号，无视频附件也能完成。
5. 创建剪辑说明文件：展示审批，允许后生成；拒绝和取消没有文件写入；同名现有文件不变。
6. 修改一个现有文本文件：展示变更，唯一匹配才执行；审批期间文件发生变化时不覆盖新内容。
7. 执行本地命令：成功、非零退出、长输出和取消均有真实状态，确认子进程退出，不从退出码推断产物。
8. 已成功生成文件后下一步失败或取消：成功文件仍可定位，失败步骤没有成功标记。
9. 两会话不同目录、多轮继续、关闭重启：上下文、目录和文件关联保持隔离，旧事件不被重写或静默删字段。
10. 已纳入发布的项目指令与技能能够影响真实任务，预算状态真实，技能内容不能绕过操作授权。
11. 在 Windows 安装包中重复核心文件、命令和视频任务，不依赖仓库根目录、开发缓存或未声明的本机工具。

所有任务使用隔离测试目录和测试素材。用户给出的真实目录可以用于其授权的只读检查，未经授权不得为了验收修改或清理其中素材。不得打印、复制或提交真实密钥和完整私人会话。

### 7.3 证据要求

- 区分单元测试、真实文件/进程集成、使用预置事件的 GUI 验证、真实模型端到端验证；不能相互替代。
- 验收记录包含基线、实际输入、实际工具、结果、相关文件及必要截图。不要粘贴无关原始长日志。
- 真实目录数量、命令退出码、产物内容等必须来自本次工具结果；不得写死一个预期测试总数。
- 模型依赖或凭据缺失时标记 SKIP，并说明缺失条件；阶段要求的真实链路未完成时，阶段保持未完成。
- GUI 必须有真实窗口或浏览器可观察证据，日志只作补充。用户指定验证工具或执行渠道时，遵守其选择。
- 同一最终代码通过检查后，只有后续修改、失败或尚未解决的疑点才需要重跑相关检查；不得无目的重复全量测试。

## 8. 分阶段合并与停止条件

默认采用一个独立问题对应一个功能分支和一次审查交付。当前 30–36 混合工作区先完成归属和收尾，不机械拆分为不存在的历史提交。

阶段通过后，按用户已有授权提交、推送和合并；没有相关授权则交付当前结果并明确哪些 Git 操作未执行。已授权连续推进且相应 Git 操作已获授权时，不逐阶段重复申请同一权限。

出现以下任一情况，停止依赖它的工作，并说明需要什么具体条件；仍可完成不受影响的只读定位和交付记录：

- 同一共享调用链仍被其他会话修改，当前验收无法绑定稳定代码。
- 核心事实丢失、旧快照损坏、取消不能停止实际操作或授权拒绝仍产生副作用。
- 必需真实验证无法执行、自动化门禁失败或审查仍有阻塞问题。
- 当前阶段需要新的数据库、第二套循环、运行时替换等超出本文选择的设计。
- 需要用户未授权的外部发布、Git 操作或其他不可逆行为。

阶段报告固定写明：

```text
Stage                  阶段编号          本次唯一交付问题。
Baseline               起始基线          分支、HEAD 与已存在的相关修改。
Changed                实际变更          用户行为变化及其生产调用链。
Validation             验证结果          实际命令、结果与证据位置。
Review                 差异审查          发现的问题、修复情况、剩余阻塞。
Real Verification      真实验收          模型、工具、GUI 和外部进程的实际覆盖范围。
Unverified             尚未验证          SKIP 的具体条件，不能写成 PASS。
Git Status             仓库状态          本轮是否提交、推送、合并及未提交范围。
Next Dependency        后续依赖          下一阶段能否开始及其具体条件。
```
