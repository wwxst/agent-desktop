## 目标与范围

当前界面服务多视频、本机会话持久化、运行时设置、会话重命名/删除与各会话多轮连续处理的视频剪辑闭环。设计目标是安静、紧凑、可扫描的智能体工作区，让主要注意力落在任务、执行过程和产物上，而不是品牌栏或装饰。

当前实现本机会话持久化与重启恢复，并支持会话重命名、删除和最小 Runtime Settings（运行时设置）；不实现会话搜索、视频预览、工作区切换、运行模式选择、预览版标签、任务队列、时间轴、拖拽、新附件类型或通用界面组件库。侧栏展示当前 Agent Desktop、项目与最近会话、“新会话”动作、项目和会话操作菜单和“设置”。空状态不得演变成欢迎营销页，也不得复制参考产品的品牌与产品概念。

设置中的“个性化”分区展示 Codex 记忆开关、本地主机选择、删除全部记忆和自定义指令入口。记忆开关保存到本机 SQLite；删除动作清空本机记忆。自定义指令入口编辑用户主目录的 `AGENTS.md`，仓库根目录的开发规则不作为用户指令编辑。入口只有在真实宿主提供读写能力时可用，编辑对话框保存后立即写入文件。

## 当前实现事实

### 插件与技能管理

插件与技能操作反馈采用用户 2026-10-11 提供的安装中、安装成功和卸载成功截图作为强制视觉规范：

- 安装、卸载、启停、更新和回滚等异步操作，进行中在对应条目右侧显示灰色加载圆环与状态文字，例如“正在安装”；该条目使用浅灰背景，动作暂时不可重复提交。详情与弹窗沿用同一加载状态。
- 成功、失败和没有对应条目的异步进度使用页面底部居中的紧凑浮动提示；提示包含状态图标、结果文字和关闭按钮，保留至用户关闭或下一次操作，不采用大型警告面板或页面内重复结果文字。多个宿主错误保留完整内容，在同一提示内可滚动查看。
- 安装成功显示白色提示、绿色确认图标、真实插件或技能图标与“已安装”文字；宿主确认存在已安装、已启用且所属插件启用的技能时，增加黑色“立即试用”按钮，只准备草稿，不自动发送。没有可用技能时不显示该按钮。
- 卸载及其他成功结果使用浅绿背景、绿色图标和文字；失败使用同一尺寸和结构的红色提示，保留真实原因，不能伪装成功。取消目录选择不显示成功。
- 列表、详情、设置和技能弹窗必须共用反馈样式；模态弹窗打开时提示位于弹窗底部并预留空间，不覆盖“使用”或表单动作，结果仍可关闭。窄窗口允许文字换行，关闭和试用按钮保持可达；暗色主题保持相同层级与可读对比。
- 技能详情安装完成后留在详情中展示结果，由“立即试用”或“使用”显式准备草稿；卸载确认与工具审批继续沿用原流程。

### 页面骨架

- 桌面布局采用“图标导航栏 + 会话侧栏 + 主工作区”三栏关系；左侧总宽 280px，主工作区承担对话和任务执行。
- 主工作区内部是可滚动对话区和 Composer；不保留独立顶部栏或顶部预留空间。
- 活跃对话只滚动历史内容，输入区占据独立布局空间，不覆盖消息；空状态内容超出窗口高度时从顶部开始滚动，欢迎内容和发送操作都可以到达。
- 默认窗口和窄窗口都保持同一层级；窄窗口只收缩侧栏图标，不把侧栏整体删除，避免顶栏变成孤立卡片。
- 新消息、当前轮活动轨迹更新和 Agent 完成时，对话区只在用户仍停留在最新内容处时跟随滚动；用户向上阅读时保留其位置，主动发送任务、切换会话或打开设置后重新回到最新内容。不引入额外滚动控件或复杂的手动上滚状态。

### 顶部栏

- 当前不显示独立顶部栏；页面顶部不保留空白占位。
- 对话与设置入口由最左侧图标栏承担，新会话与会话列表由相邻侧栏承担。

### Composer 与发送契约

- 发送按钮使用 34px 圆形蓝色主操作，箭头是 18px SVG 图形，不使用 Unicode 字符。
- 输入框为空时，发送按钮必须保留 `disabled`；处理中同一按钮变为“停止”并保持可用。
- 已有任务历史时，在输入框外下方显示紧凑的执行状态条，使用当前会话真实轮次和最近一轮模型步骤；没有历史任务时不显示空状态条。当前模型契约不提供 token 速度、总量或缓存命中事实，因此界面不展示这些指标。
- 禁用发送按钮使用默认指针，不显示 `not-allowed`，不制造“可执行但失败”的交互暗示。
- 只要有任务文本，即使没有选择主视频也可以发送；这时用户消息不显示附件，主进程向 Agent 发送纯文本任务提示（只有音轨时明确说明它不是可剪辑的主视频）。
- 只有附件没有任务文本时仍不可发送，因为当前 Desktop IPC（桌面进程通信）任务契约要求非空文本。
- “就绪”状态不常驻显示；处理中只在发送按钮旁显示“处理中”。
- 附件 `+` 按钮保留键盘可达性，但不显示额外蓝色焦点外圈。

### 无主视频任务边界

- Renderer 允许无主视频提交有文字的任务。
- Main 不再把选择视频作为所有任务的前置条件；无主视频时不虚构输入视频和输出视频路径。
- `buildAgentPrompt` 在无主视频时只补充事实：本次没有选择输入附件（只有音轨时改为「没有选择主视频，只有音轨文件」并声明音轨不是可剪辑的主输入），以及本次没有预设的最终输出路径。它不追加「一律禁止媒体工具」这类策略——用户可以在任务文字里直接给出路径，由模型对该路径调用已注册工具。
- `createVideoAgent` 在没有语音模型路径时不注册 `transcribe_audio`；选择主视频后仍按现有视频任务配置要求语音模型。
- 有主视频的剪辑任务仍沿用原有工具追踪和产物展示链路。宿主不再为任务预设最终输出路径：输出项由模型按用户要求声明，候选只写在该输出项的工作目录内，最终名称在发布时按真实磁盘占用确定——默认取 `-edited`，被占用时继续取 `-edited-2`、`-edited-3`；尚未发布不会占用任何名字，明确目标已存在时发布拒绝覆盖也不改名。

### 工作目录

- 输入框外左上方显示动态项目选择器：使用文件夹图标、当前项目的最终目录名和下箭头；名称来自当前会话和持久化项目列表，不写死具体项目。完整路径通过标题和可访问名称提供，界面不展开前级目录；未选择项目时显示“选择项目目录”。
- 打开选择器后列出当前真实项目、当前项目勾选、“新建项目”和“不在项目中工作”；选择项目切换到对应会话或创建该项目草稿，新建项目使用宿主目录选择器。
- 工作目录是任务输入上下文的一部分，因此放在输入区而不是侧栏或对话正文；它不参与发送状态，空文本禁用规则不变。
- 批准或拒绝由审批卡承担；这一行只展示结果，不提供修改或清除入口。

### 操作审批

- 宿主有待决操作时，在 Composer（输入区）上方显示一张浅色审批卡：一行提问（按操作类型区分访问目录、创建文件、修改文件或执行命令），下面用等宽字体显示宿主给出的确切路径，再下面是“允许”和“拒绝”两个动作。修改文件时，路径与动作之间并列展示“原内容”和“新内容”；长文本在各自区域内滚动，560px 以下改为上下排列。执行命令时，路径位置改为解释器、执行目录和生效超时的字段行，下面用等宽字体展示完整命令，并如实说明这是以当前用户权限执行的本机命令授权、工作目录只是执行起点而不是沙箱。
- 审批卡只展示宿主给出的操作，不提供编辑路径或改用其他目录的入口：批准的范围必须和真正要执行的操作完全一致。
- “允许”是主操作，“拒绝”是次要操作；两者都是普通按钮，不引入禁用态或倒计时。
- 用户尚未答复时，已确认的项目目录仍保持可见；待决审批只在审批卡中展示，批准前不会把未确认的目录加入项目选择器。
- 轮次结束（完成、失败或取消）后审批卡立即消失，不能让用户去回答一个已经失效的请求。
- 审批卡属于 Composer 的当前待决状态，不进入历史阅读轴：重新加载会话时不会重现旧的审批请求。
- 窄窗口下两个动作允许换行，文件变更改为上下排列；任何内容都不能遮挡路径或撑破阅读轴。

## 强制规则与不能做

### 强制规则

- 视觉修改必须保持侧栏、中央对话轴和底部 Composer 的空间关系。
- 空状态和活跃对话必须使用同一个 Composer；切换时不能丢失草稿或重建输入节点。
- 所有发送状态必须遵守“空文本禁用、处理中变停止、有文字无视频可发送”。
- 视觉参考只用于尺寸、间距、密度和层级对照；实际功能仍以当前代码和视频 Agent MVP 为准。
- 修改 Renderer 后使用 `corepack pnpm desktop:dev` 进行实时视觉验收；修改 Main 或 Preload 后重启开发进程。

### 不能做

- 不能因为参考图增加 DSH 的工作区选择、模型选择、权限选择、轨迹页、Token 统计、日志下载、搜索或视频预览入口。
- 不能恢复独立顶部栏、Logo 或品牌副标题；不加入通知等未经本轮范围确认的控件。
- 不能把省略号或状态图标做成没有真实消费者的按钮。
- 不能把无视频任务重新改回“必须选择视频”；也不能把空文本发送改成看起来可提交。
- 不能用大面积空卡片、渐变、品牌插画或高权重 Header 抢占对话区注意力。
- 不能把用户消息和 Agent 回复都做成对称气泡；Agent 回复保持平面正文，工具过程保持紧凑摘要。
- 不能把审批做成可编辑表单或把工作目录做成可自由切换的输入控件：界面只展示宿主要执行的确切操作。

### 明确禁止项

- 禁止把参考截图中的工作区选择、模式选择、预览版标签、品牌标题、模型选择器、插件入口或其他产品概念加入当前客户端。

- 禁止未经本轮需求确认就新增按钮、菜单、附件类型或运行能力；尚未实现的搜索和预览不显示占位控件。
- 禁止把空状态做成营销页、独立欢迎面板或第二套输入区；Composer 必须是当前唯一的任务输入入口。
- 发送按钮在空文本时保持 `disabled`；任务处理中变为可用的“停止”；没有选择视频但有文字时仍可发送。
- 发送按钮禁用时使用默认指针，不显示 `not-allowed` 禁止符号。
- 禁止给附件 `+` 按钮增加蓝色焦点外圈；它保留键盘可达性，但不使用高权重蓝色装饰圈。

## 页面结构

### 空对话

- 尚无用户任务、工具活动、智能体回复或错误时，欢迎内容与现有输入区组成一个整体，位于主工作区视觉中心。
- 空状态只显示“开始一个视频任务”和“选择视频，或者直接告诉 Agent 你想做什么。”，输入区仍是首要操作；不显示示例任务、推荐任务或快捷指令。
- 用户发送首个任务后，空状态整体消失；对话内容进入阅读轴，同一个输入区切换到底部停靠位置，不重建输入节点或丢失草稿。
- 默认窗口、最小窗口和窄窗口下，居中整体允许随可用高度滚动，不能把输入按钮挤出可见区域；窄窗口收缩侧栏而不是直接隐藏工作区上下文。

### 工作区侧栏

参考证据位于 `logs/codex-sidebar-reference-20261001/`。本轮吸收项目与最近分区、折叠、悬停操作、右键菜单、置顶与归档管理；不复制通知、产品模式、多窗口、聊天分叉、未读、手动拖动排序、多源文件夹和自定义标记选择器。

- 侧栏仍固定在左侧，宽度 228px，使用中性背景和细右边界；品牌保持纯文字，新会话动作使用笔形图标。项目与最近分区共用一个独立滚动区，底部不再提供已归档入口，归档对话统一从设置进入。
- 项目标题提供折叠、侧栏选项与添加文件夹；项目行显示文件夹图标和单行省略名称，悬停或键盘聚焦时显示操作菜单及项目内新会话按钮。项目区和单个项目均可折叠；折叠时保留当前任务的运行标记。
- 最近区按置顶优先、最近更新排列；当前聊天同时在所属项目与最近区高亮。创建和任务轮次更新影响排序，查看聊天、改草稿与导航不改变更新时间。
- 未发送的输入是待提交草稿，不进入项目或最近会话列表。普通入口及各项目分别复用已有草稿；反复点击“新会话”保留输入、附件和原工作目录，不新增编号会话。桌面重启恢复这些草稿，旧快照中的既有历史保持原样。
- 移除项目后未提交草稿保留输入、附件及目录；重新添加原目录并点击项目内新会话时恢复该草稿。
- 首次发送才把草稿加入历史，失败或取消也保留已提交的任务。临时标题使用完整首条任务，列表按现有规则单行省略；桌面首轮成功后由宿主模型概括标题，手动名称始终保留。命名失败保留任务结果和临时标题，并在输入区旁显示真实原因及重命名提示。
- 首条消息为纯数字时直接使用原文标题，不要求模型推测任务；模型整句返回“未提供任务内容”或“无法生成标题”的说明视为命名失败，不误拒绝“修复无法生成标题的问题”等正常任务标题。
- 每条历史均可通过删除弹窗移除；删除最后一条后历史为空，返回待提交输入页并保留已有草稿，不补出“会话 7 / 会话 8”等占位条目。宿主没有剩余运行态时创建的输入会话同样只属于草稿。
- 分区选项支持分项目显示与合并显示；分组及折叠状态随本机快照自动保存。已归档对话不进入项目与最近区，设置中的归档分类直接读取同一份会话状态。
- 会话行保持 32px 最小高度和 13px 标题，末尾省略号保留固定点击位置；悬停或聚焦显示置顶与归档快捷按钮。当前执行状态采用有可访问名称的紧凑旋转标记，不展示猜测的进度。
- 运行标记固定为 10px 正方形圆环，只在真实处理中显示；标题独占弹性与省略样式，不能拉伸圆环。窄窗口隐藏标题时仍保留运行标记，折叠项目处理中用圆环替代文件夹避免挤压菜单；完成、失败或取消后恢复。
- 项目或最近分区折叠且包含运行中会话时，分区按钮的展开箭头位置显示圆环，不额外占用标题栏菜单空间；结束后恢复箭头。
- 窄侧栏的会话列表保留滚动行为，隐藏滚动条且不预留槽位，让圆环与分区操作保持可见，不能产生横向滚动。
- 会话右键和省略号打开同一个菜单，提供重命名、置顶、移到项目、归档、删除。重命名支持 Enter 或失焦保存、Escape 取消；输入法确认不提交。点击删除关闭菜单并打开独立居中模态弹窗，使用紧凑圆角表面、右上角关闭按钮、会话名称标题、说明文字和底部取消/危险操作按钮；背景遮罩阻止操作其他界面，默认聚焦取消。取消、关闭或 Escape 关闭并返回触发位置，确认成功才移除会话；删除等待时禁止重复操作与关闭，失败在弹窗内显示真实错误并允许取消。
- 项目菜单提供项目内新会话、置顶、编辑名称、在资源管理器中打开、批量归档聊天和移除项目。批量归档在菜单内确认；移除项目关闭菜单并打开独立居中模态弹窗，使用紧凑圆角表面、右上角关闭按钮、项目名称标题、说明文字和底部取消/危险操作按钮。默认聚焦取消，取消、关闭或 Escape 返回项目入口；确认后移除列表归属并将焦点交给新会话按钮。项目名称编辑是一次整体确认，提供保存和取消。
- 菜单继续使用原生顶层浮层和触发元素锚点，靠近窗口边缘时翻转方向；滚动不能裁切菜单及项目确认面板。Escape 或点击外部关闭菜单。会话删除和项目移除共用原生模态弹窗样式，按用户确认的参考图采用 420px 最大宽度、20px 圆角与内边距、20px 名称标题和灰色 14px 说明；右上角提供轻量关闭按钮，底部操作右对齐，取消默认带蓝色焦点描边，危险操作使用浅红底和红字。窄窗口两侧至少留 16px，长名称与内容在弹窗内滚动；背景遮罩阻止操作其他界面。宿主操作失败显示真实错误，等待时禁用重复操作。
- 任务执行期间维持已有的新建、切换和会话管理禁用规则；分区折叠与分组展示可操作。
- 已归档聊天可查看历史，草稿保留；输入、附件修改和发送禁用，输入区上方提供恢复提示及动作。恢复后继续原会话，不新建模型上下文。
- 820px 以下保留 64px 侧栏：项目显示文件夹图标和操作菜单，会话继续用圆点区分；隐藏行内快捷操作，项目内新建仍通过菜单可达。图标均有可访问名称和标题，不加入横向滚动。

## 对话层级

### 用户任务

- 用户任务右对齐，不显示“你”标题和圆形头像。
- 任务正文使用参考浅蓝背景的气泡，圆角 22px，内边距为上下 10px、左右 16px。
- 气泡宽度上限为自适应正文宽度的 70.2%，同时不超过当前可用宽度的 82%；560px 以下可放宽到 86%。
- 已提交附件位于气泡上方并右对齐，使“输入文件”和“任务文字”成为同一用户动作。

### 智能体回复

- 智能体回复保持平面正文，不使用对称聊天气泡。
- 成功回复不显示角色标记和角色文字，直接从正文开始；16px 轻量图形加 12px 次要文字的标记只用于“已停止”和“任务失败”终态，它只说明状态，不充当头像。
- 正文使用 14px 字号和 24px 行高，沿用共享正文宽度轴。
- 正文按最小 Markdown（轻量标记文本）子集渲染：段落、无序/有序列表、围栏代码块、行内代码、加粗和链接；未支持的形式（标题、表格、引用、图片）保持原文，不生成额外结构。用户任务气泡始终按纯文本展示。
- 行内代码用于真实路径、工具名和短命令，长路径在正文宽度内断行；围栏代码块在自己的区域内横向滚动，超长命令不得撑宽阅读轴或页面。
- 链接只在明确的 web 协议上渲染为可点击锚点；桌面宿主把外部地址交给系统浏览器，窗口本身既不导航也不新开窗口。
- 处理期间实时文本沿用同一正文渲染，并在末尾显示表示仍在输出的光标；完成、取消或失败后光标不再显示。
- 处理态、失败态和成功回复沿用同一正文轴；失败使用错误语义色，不增加大型警告卡片。
- 处理期间收到实时文本增量时，在同一正文轴直接展示该临时文本；增量到达前保留紧凑的处理指示，完成、取消或失败后临时文本不再显示，只保留最终回复或终态说明。
- 每轮 Agent 回复拥有自己的活动轨迹和产物；完成新一轮后不得覆盖或混入前一轮内容。
- 界面不显示执行追踪编号；该编号仍由主进程生成并写入本地追踪日志，任务结果契约保持不变。

## 输入区

- 输入区使用 22px 圆角、轻描边和柔和阴影，与页面保持同色表面。
- 空会话文本区最低 52px，活跃会话最低 36px，行高 24px；文本与工具栏之间留 12px。随内容自动增长，最大 128px；不暴露手动缩放手柄。Enter 发送，Shift+Enter 换行，中文输入法组合确认不触发发送。
- 添加附件按钮固定为 28px 圆形，内部使用居中的 14px SVG 加号；悬停时圆形背景明确加深。发送按钮固定为 34px 圆形，二者分别位于左下和右下。
- 发送按钮是唯一高权重操作，使用蓝色主操作色；不可发送时降低透明度，但尺寸和位置不变。
- 空文本时发送禁用；处理中按钮切换为方形停止图形并保持可用；没有视频但有文字时按钮可用，提交的用户消息不显示空附件标签。
- 常态不显示“就绪”。处理任务时可以在发送按钮旁显示低权重的“处理中”。
- 任务成功后清空草稿但保留当前视频集合，任务失败后保留草稿，方便修改或重试。

## 附件

- 附件对齐 DeepSeek Harness（参考客户端，DSH）的 240×64px 文件卡，0.5px 边界、16px 圆角；一次任务可分一次或多次选择多个输入文件，后续选择追加到现有集合。
- 图形容器占 28px，文件名使用 14px 中等字重和 22px 行高，下一行使用 12px 弱化文字显示角色（“视频”或“音轨”）。
- 主视频使用播放三角、音轨使用波形描边：两类输入必须在卡片上可区分，不能只靠文字标签。音轨波形为描边绘制，需显式声明 `stroke` 才能与三角同样清晰。
- 长文件名保持单行并显示省略号，不能扩张卡片或遮挡取消按钮；完整文件名通过卡片标题提供。
- 多个附件以 8px 间距横向并排，超出输入区后横向滚动，不换行增加 Composer 高度。
- 附件轨道保留可见的细滚动条；可移除附件始终为取消按钮预留空间，悬停和键盘聚焦不挤动文件名，触摸设备常显时也不遮挡名称。
- Composer（输入区）中待提交附件的右上角提供 18px 圆形取消按钮；桌面端悬停或键盘聚焦时显示，触摸设备常显。点击后必须同步移除 Renderer（渲染层）和 Electron Main（主进程）中的对应附件。
- 已提交附件使用相同文件卡片结构，但不提供取消或预览操作。
- `+` 附件按钮不显示蓝色焦点外圈；键盘焦点仍可到达按钮，但视觉权重保持为轻量圆形控件。

## 活动轨迹

- 活动区标题行高度为 33px，带底部细分隔和矢量展开箭头；标题只汇总本轮真实工具调用次数，不把模型步骤计入工具数量。活动行最小高度为 24px，13px 动作文字。
- 活动行按真实执行顺序排列：模型步骤行显示“分析任务”和该步真实产生的工具调用数量（0 表示该步直接生成回复）；工具行显示中文动作名和技术工具名。
- 每行依次显示事件类型图标、动作名、圆点分隔、技术工具名或分析结果、真实文件引用、执行状态和耗时；技术工具名必须紧跟在中文动作后面，不能用虚构命令替代。
- 文件引用只出现在宿主确认过的真实路径上：输入文件显示文件名，输入目录和输出目录以 `/` 结尾，输出文件带 → 前缀；点击交给宿主定位，定位失败时在该行内显示真实错误文字，不弹窗、不静默失败。
- 状态只使用执行中、已完成、失败、已停止四种真实状态；耗时来自真实执行时间，超过 1 秒改用秒或分秒展示。
- 中文动作名与技术工具名在空间允许时保持同一行；状态和耗时靠右，便于纵向扫描。
- 行本身不使用卡片边框和纵向连接线，只在悬停时显示轻背景；整个区域沿用 Harness 的平面披露行密度。
- 工具完成后，只有宿主提供真实结果详情的行才显示二级展开箭头：`read_file` 展示带真实行号的文件片段，`list_directory` 展示真实文件与目录项，`search_text` 展示真实文件、行号和匹配内容，任意工具失败展示其真实错误消息。详情使用行内浅底披露区，不把每条结果做成独立卡片。
- 文件、目录和搜索结果沿用各工具现有上限；界面不重新扫描磁盘、不补全被工具截断的内容，也不把技术工具名伪装成 Shell Command（命令）。详情随所属活动和会话快照恢复。
- 命令详情分别展示标准输出和错误输出两条流，并展示退出码或超时终止；执行期间由宿主按小批次推送已经收到的有界输出，命令结束后由权威终态覆盖。输出被截断时显示被省略的字节数，界面不自行累积超出宿主上限的内容。
- 处理中默认展开并允许用户收起；完成后默认折叠为真实工具调用次数，并允许用户重新展开。
- 每组活动只显示在产生这些事件的当前 Agent 回复中，多轮之间不得合并活动列表。
- 界面不得出现未由真实事件、参数或结果产生的进度、命令、文件操作或测试数量。
- 5 至 10 项活动同时展示时仍应在默认窗口中保持紧凑，不得让单行信息变成多层面板。

## 产物区

- 产物是智能体回复的一部分，使用参考的浅底文件卡：最小高度 60px、18px 圆角和轻边界；整张卡片不伪装成已可预览的点击区域。
- 产物图形容器固定为 40px，图形按真实产物类型区分：只有视频使用播放三角，字幕和文本使用不暗示可播放的线条；文件名省略显示并提供完整标题提示。
- 下一行显示真实类型与完成状态：视频为“视频 · 已完成”，`.srt` 为“字幕 · 已完成”，`.txt`/`.md` 为“文本 · 已完成”，其他扩展名统一显示“文件 · 已完成”，不把非视频产物伪装成视频。
- “打开文件”是文字型次要操作，保持可见但不与发送按钮竞争视觉权重。
- 多轮产生的产物分别留在对应 Agent 回复中；同一轮真实成功生成多个持久文件时，每个文件各有一张卡片。“打开文件”按该卡片记录的真实路径定位文件，不按文件名猜测，也不始终打开最新产物。
- 文件已被移动或删除时，“打开文件”展示宿主返回的真实错误，不静默失败。
- 窄窗口允许打开动作换到文件信息下方，但不得与文件名或图形重叠。

### 交付结果

- 本轮真的声明过视频输出项时，在产物卡之前显示一块“交付结果”区域：首行是 `交付结果 N/M`，其中 M 来自声明列表、N 来自真实发布事实，两者都不由模型文字决定。
- 每项一行：已交付项显示真实文件名与“已交付”；未交付项显示输出项序号与“未通过”“无法确认”或“未完成”，并在下一行显示宿主给出的真实原因（例如实际时长不在要求范围内、缺少证据、尚未发布）。
- 这块区域只展示宿主计算出的结论，不自行判断某项是否合格；已交付文件的打开动作仍由产物卡承担，因此同一轮不会出现两套打开入口。
- 取消或失败终态同样展示已经产生的逐项结果：整轮停止不回滚已经交付的文件，也不把未完成项说成全部完成。
- 没有声明过输出项的普通问答与通用文本任务不渲染这块区域，也不显示“0/0”这类占位。

## 主题与图形

### 执行交互与终端

- `ask_user` 等待时，在主输入框上方显示独立问题区，包含选项、自由文本、提交和跳过。主输入草稿保留，发送仍处于停止状态；回答后在同一轮继续，恢复后没有待答问题。
- 公开过程说明在已有执行过程列表中按真实步骤出现，位于对应工具之前；最终回复只显示一次，空文字不占行，不展示内部推理。
- 模型重试时在同一模型活动内显示真实等待与次数；不增加假的模型步骤或工具活动。
- 子任务详情嵌套在委派工具行下，分别显示标题、执行状态、摘要；失败、已停止和预算耗尽明确区别于完成。
- 会话终端位于输入框上方，可折叠，运行时可关闭。显示真实目录与状态，用 xterm 渲染中文和控制序列；输出保留上限与被省略字节数可见，恢复后显示“连接已结束”。
- 启动终端与每次输入都有独立审批，完整输入以字符串转义形式显示，确保换行和控制字符也可核对；终端属于当前会话，切换会话时恢复对应历史。
- 桌面允许 xterm 必需的动态样式；脚本仍只允许本地资源，渲染层不连接外部服务。

- 页面使用白色基础背景、中性灰文字与边界、蓝色主操作、绿色成功状态和红色失败状态。
- 颜色的具体实现由 `packages/client/src/styles.css` 中当前使用的语义变量负责；本文不复制 HEX 值。
- 不使用大面积单色渐变、装饰光斑、嵌套卡片或品牌插画。
- 当前少量图形不构成引入组件库的理由。若未来真实界面需要统一图标集合，必须先说明消费者与依赖价值，并遵守工程基线。

## 验证流程

自动验证使用项目统一入口：

```bash
corepack pnpm check
corepack pnpm desktop:build
```

视觉验证必须启动正确的应用：

```bash
corepack pnpm desktop:dev
```

开发验收使用 `desktop:dev`，这样 CSS 和 React 修改会即时反映到窗口；生产构建验收使用 `pnpm desktop`。不得直接启动裸 `electron.exe`。确认窗口标题、侧栏、滚动区域和输入区均属于 Agent Desktop，而不是 Electron 默认欢迎页。

测试只验证用户可观察行为，不锁定颜色 HEX、CSS class、像素截图或具体 DOM 层级。视觉验收通过必须来自真实渲染观察，不能由测试或构建通过代替。
