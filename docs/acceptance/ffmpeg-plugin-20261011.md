## 阶段二：只读媒体能力

复用原 MCP 服务、工具实现和参数，不增加包或框架。Desktop 将启用服务的七项只读能力作为同一组通用 `Tool` 注入视频应用层；应用层移除直接只读注册。新增 `extract_full_video_frames` 仅把既有逐帧算法暴露为可注入工具，使语义验收不再直接执行 FFmpeg 抽帧或音频提取。内部调用仍经过相同宿主授权、MCP 审批、钩子和取消。

抽帧和音频输出仅允许已确认工作目录或来源已授权的视频输出项工作目录。目录联接越界在 MCP 审批前拒绝；语义检查临时文件位于输出项工作目录并在结束时清理。六字段 Probe 结构、字符串音频结果和其他既有结构化结果保持；解码、黑段和抽帧结果在 MCP 边界校验。服务对每个媒体输入限制普通容器及本地文件协议，保留既有媒体算法。

本机完整门禁：59 文件 641 项测试通过，构建通过。新增真实 MCP + Agent 同一轮顺序执行七项工具：带音轨 H.264 输入、完整解码、无黑段、全片/局部抽帧、全部十帧与时间戳、16 kHz 单声道 PCM 音频；独立 ffprobe 复核音频格式。全组未授权输入、网络 URL 和输出目录联接拒绝；禁用及卸载后工具列表为空。日志 `stage-2-focused.log`、`stage-2-final-check.log`、`stage-2-build.log`。

阶段审查：只读专业工具没有应用层自动回退，Core/Loop/Session 公共契约未修改；视频写出仍保留原注册，待下一阶段迁移。语义预算、候选摘要和独立判断规则保留。`Review Decision: PASS`。旧 Probe 原生进程取消/断开用例继续执行。此阶段尚不代表完整 FFmpeg 插件分发。
