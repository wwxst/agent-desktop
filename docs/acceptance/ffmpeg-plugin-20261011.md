## 阶段二：只读媒体能力

复用原 MCP 服务、工具实现和参数，不增加包或框架。Desktop 将启用服务的七项只读能力作为同一组通用 `Tool` 注入视频应用层；应用层移除直接只读注册。新增 `extract_full_video_frames` 仅把既有逐帧算法暴露为可注入工具，使语义验收不再直接执行 FFmpeg 抽帧或音频提取。内部调用仍经过相同宿主授权、MCP 审批、钩子和取消。

抽帧和音频输出仅允许已确认工作目录或来源已授权的视频输出项工作目录。目录联接越界在 MCP 审批前拒绝；语义检查临时文件位于输出项工作目录并在结束时清理。六字段 Probe 结构、字符串音频结果和其他既有结构化结果保持；解码、黑段和抽帧结果在 MCP 边界校验。服务对每个媒体输入限制普通容器及本地文件协议，保留既有媒体算法。

本机完整门禁：59 文件 641 项测试通过，构建通过。新增真实 MCP + Agent 同一轮顺序执行七项工具：带音轨 H.264 输入、完整解码、无黑段、全片/局部抽帧、全部十帧与时间戳、16 kHz 单声道 PCM 音频；独立 ffprobe 复核音频格式。全组未授权输入、网络 URL 和输出目录联接拒绝；禁用及卸载后工具列表为空。日志 `stage-2-focused.log`、`stage-2-final-check.log`、`stage-2-build.log`。

阶段审查：只读专业工具没有应用层自动回退，Core/Loop/Session 公共契约未修改；视频写出仍保留原注册，待下一阶段迁移。语义预算、候选摘要和独立判断规则保留。`Review Decision: PASS`。旧 Probe 原生进程取消/断开用例继续执行。此阶段尚不代表完整 FFmpeg 插件分发。

## 阶段三：写出能力与交付

七项写出能力全部由 MCP 提供，视频应用层只包装实际注入的工具，没有具体 FFmpeg 实现的生产导入或自动回退。宿主在审批前验证所有输入（含音频、字幕、拼接数组）及声明输出项目录；声明和发布也复核附件、来源与最终目标权限。插件不能返回正式产物元数据，写出成功必须对应实际授权候选。原有生产调用、摘要、解码、黑段、语义判断和独占发布规则继续负责最终交付。

真实 MCP 与 Agent 循环生成七份独立成片，分别验证裁剪、拼接、配音、字幕、缩放、裁切和变速；第八份损坏输入失败且不能发布。独立解码和 ffprobe 复核格式、尺寸、时长、音轨，像素断言确认红蓝拼接顺序及字幕烧录；重复发布失败且原文件字节不变。未声明输出、未授权音频/字幕/目标均在 MCP 调用前拒绝。原生进程用例覆盖探测与写出取消及 stdin 断开清理。

完整门禁 60 文件 643 项通过，构建通过；真实 Windows Electron 的插件审批、语义验收、交付及禁用生命周期通过（8.1 秒）。模型与视觉请求使用确定性协议夹具，不代表真实模型理解验收。日志：`stage-3-final-check.log`、`stage-3-build.log`、`stage-3-electron-retry.log`。Windows CI 的音频输出短路径别名断言同步改为真实路径。

阶段审查：未修改 Core/Loop/Session 公共契约及既有媒体算法；保留正式发布唯一入口。`Review Decision: PASS`。回退此阶段恢复只读插件加内置写出，不删除用户成片或会话。

## 限制与后续

Windows 已验证的是本开发机上的干净应用配置和隔离 PATH，未执行全新操作系统虚拟机。模型与视觉使用协议夹具，不代表真实模型理解质量测试。签名、线上自动更新及未来二进制再托管的完整对应源码分发未实施或未验证；本轮安装直接从供应商下载并保留许可通知。归档和历史版本缓存供重装/回滚保留，不删除用户媒体或会话；尚无自动回收平台。

正式插件仅支持 Windows x64，其他平台通用任务和 CLI 继续运行。通用终端可能执行用户另装的 FFmpeg，专用插件卸载不等于禁止操作系统所有媒体命令。Whisper 和 Vision 尚有应用层具体实现依赖；后续沿实际工具注入、宿主权限、审批、取消与受阻结果迁移，各自模型资产按明确需求实施。
