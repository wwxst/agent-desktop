## 本轮确认的当前版本边界

1. `apps/desktop/src/main/desktop-database.ts` 使用同步短连接和参数化语句；多文档保存采用 `BEGIN/COMMIT/ROLLBACK`。`session-persistence.ts` 的 `appendMany`、`commitStart` 和 `persist` 在成功写盘之后才推进内存，首次保存失败锁存为同一个 `SessionPersistenceError`。任务起点事件、消息身份绑定及展示快照在同次提交中保存。

2. `apps/desktop/src/main/index.ts` 的任务入口先校验当前会话、消息身份、附件与展示快照，再保存任务起点，之后才读取模型配置、准备插件、执行钩子或请求模型。重启对未终结任务追加中断并重建展示，不自动重放工具；用户恢复要求准确当前任务及恢复链最新轮次。

3. `apps/desktop/src/main/agent-task-state.ts` 的 `taskToolGate` 在每次实际调用前读取当前事件，阻止未知外部效果后的新外部调用，同轮相同拒绝不再次审批，恢复链已完成的相同外部调用不再次执行。`packages/session/src/projections.ts` 使用准确调用身份关联结果，整调用核验才能解除未知效果；部分文件事实不能代替整调用结论。

4. `apps/desktop/src/main/tool-approval.ts` 的决定只接受当前请求标识和布尔批准；执行参数由宿主持有，迟到决定失效。取消信号结束待决审批。Main 在执行期间允许保存下一轮对话模型选择，其他运行时改动拒绝；已启动 Agent 使用本轮配置，不因下一轮选择被改写。

5. `apps/desktop/src/main/extension-runtime.ts` 在插件启动审批后连接服务，工具调用审批通过后同步提交检查点，再发送实际 MCP 请求。拒绝保持 `denied`，调用后的断连、服务失败或无法确认的结果保持 `unknown-outcome`。保存失败与取消原样传播。已有未知效果的恢复不准备插件或执行生命周期钩子，只提供当前核验工具集。

6. 只有来源、插件身份和服务名均符合随包插件的工具才获得 FFmpeg、Whisper 和 Vision 的公开工具名。Vision 配置缺失或路由不可用时不启动对应服务，插件禁用或卸载不能被内置视觉工具绕过。视觉密钥仅通过受控进程环境注入，不进入公开审批或工具参数。

7. `ffmpeg-tool.ts`、`whisper-tool.ts` 和 `vision-tool.ts` 复用当前宿主目录、附件和候选事实授权，先解析真实路径再审批或调用；模型声明与插件审批不能扩大文件访问授权。结构化结果按当前工具契约转换，调用后的损坏结果保持未知执行语义。语义验收消费同一已授权媒体适配器。

8. `runtime-settings.ts` 把供应商目录及加密密钥一次提交；等待加密依赖完成后才读取最新设置，避免覆盖等待期间已保存的外观和记忆配置。`safe-storage.ts` 在 Windows 等待实际系统主密钥持久化，监视真实目录以避开短路径原生崩溃；等待或读取失败时不提前提交凭据。模型、插件及账户令牌共用这一边界。

9. `packages/video-agent/src/delivery-tools.ts` 的正式发布要求最新候选、最新全项通过的验收、未重复发布及候选摘要一致。复制前保存检查点，目标以 `wx` 独占创建；已有文件不覆盖，失败只清理本次创建的目标。权限与磁盘错误不伪装成自动换名成功，清理失败保留未知结果。

## 实际发现及修正

现有 `apps/web/tests/browser/desktop-vision.pw.ts` 的 `missing-key` 场景仍把无密钥的备用视觉候选设为已启用。当前 `saveRuntimeSettings` 明确拒绝启用未配置密钥的备用模型，因此该旧夹具会在开始工具可见性检查前失败。

最小修正为保存该候选时设置 `fallbackVisionEnabled: false`，沿用既有 `missing-key` 的无 `analyze_images` 与零上传断言；生产配置校验保持不变，没有新增场景或弱化有效断言。无密钥时的启用拒绝由当前设置契约和已有运行时设置测试覆盖。

其他已同步的既有客户端/浏览器夹具使用四项模型能力声明和 `fallbackVisionModel/fallbackVisionEnabled`，不再把旧 JSON 设置文件当当前 SQLite 配置入口；移除旧 Whisper 手动路径配置，由插件模型管理消费当前契约。
