发现：移除默认能力的回归断言没有覆盖 `detect_black_segments` 和 `extract_video_range_frames`（`packages/video-agent/tests/video-agent.test.ts:15`）。已补全十四项专用工具的缺席断言，并保留交付规则可用的断言。没有发现仍在生产入口注册 FFmpeg 具体实现的路径。

复核：对 Core、Loop、Session、Tools、Model 的基线差异为空；宿主主进程及应用层没有 FFmpeg 实现导入或进程调用。原内含服务明确停用，只有独立受控插件映射公开名；实际未连接服务不满足技能依赖。CLI 是显式本机实现消费者。应用层 FFmpeg 仅保留测试开发依赖，没有新增包、框架或核心协议。聚焦应用层及交付 11 项通过。

## 第二轮：功能与安全

源码：`apps/desktop/src/main/ffmpeg-tool.ts:127`、`:173`、`:190`、`:203`，`packages/video-agent/src/delivery-tools.ts` 的生产归属、候选摘要和发布消费者。

发现：MCP 返回 `complete: true, frames: []` 时，宿主曾将空列表视为完整覆盖（`:173`）。已拒绝这种异常成功，避免语义检查缺少实际画面却进入判断；加入边界回归用例。

复核：源视频、音频、字幕及拼接输入均在审批前解析真实路径并授权；遍历、URL、网络路径、目录联接和未授权邻居文件拒绝。目标及候选分别经过声明、写出、发布权限复核；候选不能自行获得目录授权。MCP 错误保留原消息，取消传播原信号；写出必须对应实际候选且不能携带正式产物元数据。新增伪造产物/不匹配写出结果用例均拒绝。原生进程取消经过 Agent 后，没有成功生产记录或交付记录。

不同证据：真实七种写出、八个独立输出项（七份发布、一份失败），独立全文件解码、格式/音轨/时长和像素检查；字幕可见像素及拼接颜色顺序通过。额外真实长中文路径、静音 MPEG-4、不同尺寸和间接网络输入用例通过。完整帧、音频及 Probe 的内部调用仍经同一审批，最终证据保存在语义检查的结果中，未伪造独立 Session 事件。

## 第三轮：工程与发布

源码：`apps/desktop/package.json:10`、`apps/desktop/src/main/ffmpeg-runtime.ts:25`、`:43`、`apps/desktop/src/main/extensions.ts:366`、`:498`、`:506`、`:588`，`resources/plugins/ffmpeg/runtime.lock.json` 和 `NOTICE.md`。

发现及修复：

- 迁移后的工作区仍有生成的旧 `video-editing/dist/probe-media.cjs`，会被资源通配打入安装包。构建现在只清理这一个已废弃生成文件；真实覆盖安装后确认文件不存在。
- Node 下载栈不读取 Windows 系统代理，真实下载停滞。改用 Electron 网络栈，供应商真实下载、摘要验证、安装和重装通过。
- Windows CI 的递归监视器因短路径别名触发 libuv 原生断言。监视根目录统一真实路径；恢复完整测试后暴露的技能路径断言也改为比较真实路径。没有跳过核心用例。
- README、工程及架构文档仍描述 Probe 试点和手动程序路径，已同步正式独立插件边界。

不同证据：真实 NSIS 首次安装和覆盖安装均返回 0，程序安装在中文、空格目录；覆盖后会话数据库和插件程序摘要不变，旧会话、附件及插件启用状态可恢复。最终安装版的中文配置目录完整验收和覆盖恢复验收共两项通过（1.3 分钟），应用 PATH 仅含 Windows 系统目录，未设置媒体程序路径。插件真实安装、禁用/启用、卸载/重装、更新/回滚、拒绝审批、任务锁定、成片发布和重启通过。更新使用隔离资源的 `1.0.1` 元数据夹具，不宣称存在线上新版。

Windows x64 资源来自 FFmpeg 官方下载页所链接的 Gyan，归档与程序摘要锁定，版本及必要构建选项实际执行检查；安装保留 GPLv3 许可和供应商构建说明。安装包未包含 FFmpeg 二进制，安装插件时直接从供应商下载。归档缓存和回滚目录属于插件管理，不删除用户视频、配置或会话。

## 实际验证边界

当前机器为已有开发环境的 Windows；验收使用干净应用配置及移除工具 PATH 的进程环境，没有声称使用全新 Windows 虚拟机。测试驱动可使用本机媒体程序生成输入并独立复核；产品及插件使用安装目录程序。模型和视觉网络响应是确定性协议夹具，不是在线模型理解质量评测。原生取消夹具验证进程与 Agent 取消事实，真实媒体正常处理另有独立验证。

安装包与媒体程序未完成代码签名，没有发布 Release、验证线上应用自动更新或重新托管 GPL 二进制。未来分发二进制须随实际分发方式补齐对应源码、第三方库许可和签名流程。正式插件平台目前仅 Windows x64；Whisper、Vision 的具体实现仍留在应用层，下一轮可沿同一工具注入、宿主授权、审批与能力缺失契约迁移，模型及共享资源管理独立立项。
