# SQLite 存储迁移验收

日期：2026-10-01。代码位于当前功能分支，尚未提交或合并。

## 变更范围

原来的会话、运行时设置和加密密钥分别写入三个 JSON 文件。现在统一使用 Electron 用户数据目录中的 `agent-desktop.sqlite`，由 Node.js 自带的数据库模块访问。

```text
English term          中文名称          介绍
SQLite                本地数据库        保存桌面应用的会话、设置和加密密钥。
Snapshot              完整快照          保持当前状态结构，数据库记录中保存 JSON 内容。
Transaction           数据库事务        会话整体保存，设置与密钥一起提交，失败时保留旧数据。
Legacy Import         旧文件导入        启动时解析并导入尚不存在的记录，原文件保持不变。
Execution Trace       执行追踪          继续使用现有 JSONL 诊断日志，与数据库状态分开。
```

数据库表为 `desktop_documents`，记录键只有 `session-state`、`runtime-settings`、`runtime-secrets`。会话模型、解析规则、进程通信与系统密钥加密方式沿用原实现。数据库已有记录优先；不再向旧 JSON 文件写入。数据库损坏或旧数据解析失败会明确报错，不覆盖为空状态。

## 真实桌面验收

脚本为 `logs/verify-sqlite-storage.mjs`，结果为 `logs/sqlite-storage-1790826348566/result.json`；前后截图分别为同目录的 `before-restart.png` 与 `restored.png`。全部操作使用独立临时用户数据目录。

- 在同一用户目录用真实系统安全存储生成旧版密文，保留加密上下文后模拟旧版三个 JSON 文件。
- 迁移两个会话、旧任务事件、草稿、终端历史、设置和密钥；原 JSON 文件内容未改变。
- 通过真实主进程与本地模型服务继续执行一轮 `read_file`，第二次模型请求包含文件的真实结果，旧会话上下文也随请求恢复。
- 新建并删除会话、保存新设置与新密钥后正常关闭；数据库保留两会话、当前会话、新增事件和未发送草稿。
- 重启恢复数据库中的新设置及草稿，证明旧 JSON 不覆盖数据库记录；设置接口不回传密钥，数据库文件不包含测试明文密钥。
- 终端恢复为已断开的历史，启动时无模型请求，也没有重放历史命令。
