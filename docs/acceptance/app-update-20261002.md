# 应用更新入口与 Windows 安装包验收

## 需求与范围

用户确认更新入口位于最左图标栏底部、设置上方，点击直接安装，不打开版本详情。实现范围为桌面更新器、预加载桥接、共享客户端图标和当前 Windows x64 安装包。更新不进入智能体核心，不增加设置字段、远程市场、发布自动化或版本浏览页面。

```text
Background Download      后台下载        启动检查正式发布版本，下载完成后才允许安装。
Direct Installation      直接安装        点击入口先保存当前会话，再调用安装器并重新启动。
Local Verification       本地验收        校验构建、真实运行时、传输、界面与安装前保存。
Online Upgrade           线上升级        使用正式发布的新版本覆盖已安装版本并验证重启。
```

## 实现与审查

- 桌面宿主使用已存在的公开仓库 `wwxst/agent-desktop` 作为固定发布源，自动下载，普通退出不安装。开发模式没有安装更新入口。
- 导航栏显示宿主事实：下载中禁用、就绪为蓝色圆形下载图标、点击直接安装；失败显示真实原因与重试。任务运行时不能安装，重复安装被拒绝。
- 安装前复用窗口关闭的终端收尾与客户端快照提交，保存失败保留窗口与已下载更新；已保存后的更新退出不重复握手。
- 安装包保留原应用身份和用户数据路径。真实运行发现归档路径不能用于搜索子进程，因此应用文件直接分发，避免给工具引入桌面平台判断。原生终端使用随依赖提供的 Windows x64 稳定接口二进制。
- 审查发现安装器失败后的再次安装需要重新清除保存完成标记，已修正。仅新增真实消费者的依赖与契约，没有新软件包、智能体逻辑或占位按钮。

```text
Review:
- Findings: 打包搜索路径及再次安装的保存完成标记需要修正。
- Required changes: 直接分发应用文件；每次获准安装重新开始保存收尾。
- Decision: PASS
```

## 验证结果

- `corepack pnpm install --frozen-lockfile`：通过。
- `corepack pnpm check`：51 个测试文件、555 项测试和 19 个包的架构检查通过；覆盖下载/就绪、直接安装、保存失败、重复点击、失败重试及预加载监听清理。
- `corepack pnpm desktop:package:win`：通过，生成安装包、更新元数据和文件块映射。该命令包含正式桌面构建，使用禁止发布选项。
- 浏览器更新、侧栏和设置验收：12 项通过、2 项跳过重复窄窗桌面持久化；更新图标、无详情弹窗、下载禁用、错误重试、桌面与窄窗布局通过。
- 桌面更新验收：2 项通过、2 项跳过重复窄窗桌面验收。生产构建 Main（桌面主进程）、Preload（预加载桥接）与 Renderer（渲染层）连接真实 Electron（桌面运行时）、SQLite（本地嵌入式数据库）和更新软件开发工具包。仅发布源切到本地测试服务并拦截最终安装边界；传输真实完成并校验摘要，安装调用时数据库已包含当前草稿，尚未点击时不会调用安装器。
- 正式打包程序真实启动：版本 `0.0.2`、应用名 `@agent-desktop/desktop`；随包搜索程序返回成功，原生终端实际输出 `packaged-terminal`，更新桥接可读取状态。
- 已人工查看真实桌面与 800×600 窄窗截图，更新图标在设置上方，图标尺寸与底部间距稳定。

命令证据：`logs/app-update-{check,package,browser,desktop}.txt`。桌面截图、安装前保存记录和打包资源结果：`logs/app-update-20261002/`；浏览器截图：`apps/web/logs/app-update-20261002/`。
