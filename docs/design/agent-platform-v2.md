# 通用智能体平台第二版实施设计

本次实施以 [基线审计](../acceptance/architecture-audit-20261016.md) 为起点，需求为用户提供的《agent-desktop Codex Architecture Alignment V2》。当前状态是实施中；本文不宣称尚未完成的能力已经可用。

```text
Goal          目标        形成通用智能体运行时与统一能力执行模型，继续保护媒体交付。
Problem       问题        Desktop 控制面与工具执行分散，通用能力和长视频恢复尚有缺口。
Impact scope  影响范围    核心契约、应用组装、正式能力、持久化、客户端事实消费及文档。
Non-goals     非目标      不接真实图像或视频生成，不复制第三方私有协议，不建设通用调度平台。
```

## 控制面与事实来源

运行时先在当前会话保留唯一活动轮次，宿主原子提交起点后才允许准备扩展或调用模型。准备、模型、工具、审批等待和收尾共用取消信号。已有循环负责步骤算法，原 Session 负责事实；运行时负责提交、排他、取消、恢复入口与状态订阅，不持有 Electron、SQLite、媒体或供应商协议。

运行时优先位于现有 `agent-loop` 包内，直接复用 `prepareTurnStart` 与 `runStartedTurn`，不为单一职责拆出无必要新包。新能力通过具体工具进入统一路由。审批继续复用宿主现有决策入口，操作系统专属边界留在宿主适配器。

## 阶段与完成标准

```text
Phase 0      基线审计      已记录当前源码、分类与修改前门禁。
Phase 1–2    控制与事实    运行时、提交、轮次生命周期、事件封装及配置快照。
Phase 3–4    统一执行      工具路由、能力目录、结果、并行、输出、审批与执行边界。
Phase 5–6    模型与上下文  通用供应商配置、有效能力、推理配置、预算与压缩。
Phase 7–8    子任务与代码  运行时复用、权限继承、补丁与只读版本控制工具。
Phase 9–11   通用能力      真实浏览器、Windows 无障碍操作与文档读取。
Phase 12–16  媒体与扩展    分段作业、检查点、技能、钩子和统一产物。
Phase 17–20  组装与文档    宿主职责、恢复、无消费者兼容代码及依赖方向收口。
Phase 21     最终验收      全部门禁、三轮独立审查、双平台持续集成与真实验收。
```

具体实现随真实消费者和验证证据推进，不预建调度器、通用工厂或第二份事实存储。需要暂停等待用户输入或审批时，必须保留原调用并在答复后继续。恢复已中断任务时创建明确关联的新轮次，保留已完成和未知效果，不能重新执行整轮。

功能分支可按大阶段提交并推送；正式合并另受工程门禁和合并授权约束。最终报告使用任务指定的 `docs/acceptance/agent-platform-v2-final-20261016.md`，未验证、未实现与外部阻塞必须分别陈述。只有全部必要条件满足才能给出最终通过结论。
