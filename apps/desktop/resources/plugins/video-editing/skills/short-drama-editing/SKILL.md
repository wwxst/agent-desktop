# 短剧剪辑

1. 先确认输入视频、目标画幅（横屏或竖屏）、目标时长、剧情重点、是否保留原声和是否需要字幕；这些信息会影响剪辑边界时再调用 ask_user。
2. 使用 probe_media 检查每个来源的时长、画面尺寸和音轨。多个来源需要合并时，先分别确认来源顺序和它们在剧情中的作用。
3. 有对白、旁白或关键台词时，使用 extract_audio 和 transcribe_audio 建立完整语音时间轴。根据 segments 找到开场钩子、冲突、转折、高潮和收束等候选剧情区间。
4. 剪辑边界或人物动作依赖画面时，对候选区间使用 extract_video_range_frames 和 analyze_images；对白时间轴足够明确的固定边界不额外调用视觉工具。
5. 每个保留区间都从原视频分别使用 trim_video 生成候选片段，保留自然的说话和动作进出点，再按剧情顺序使用 concat_videos 拼接。不要把上一个候选文件当作下一个不连续片段的来源。
6. 用户要求竖屏或指定尺寸时，使用 crop_video 和 resize_video 调整画面；不要声称已经完成主体跟踪或智能补边，这些能力当前没有对应工具。
7. 用户提供字幕文件，或明确要求把已确认的对白做成字幕时，先在已确认工作目录中准备 `.srt` 文件，再使用 add_subtitles 烧录。创建字幕文件需要遵守 write_text_file 的审批和目录边界；没有可用的文本文件工具时说明缺口。
8. 需要保留原声之外的音轨时使用 add_audio；不要声称已经生成音乐、音效或完成自动混音。音轨路径和来源必须来自实际文件或 Tool Result。
9. 需要产出视频时，先调用 declare_video_outputs，逐项写明来源、目标和用户明确提出的时长、画幅、字幕、内容等验收要求。候选只写入返回的 workingDirectory。
10. 候选生成后，使用 decode_video 检查完整可解码性，并按声明调用 probe_media、detect_black_segments 和必要的 check_video_semantics；只有 validate_video_candidate 的全部检查通过后才调用 publish_video_output。
11. 无法从语音或画面证据确认剧情、人物连续性、口型同步或字幕准确性的部分，明确报告受阻或需要用户确认，不能把模型推测当成验收结果。

短剧技能负责整理已有素材和证据支持的剪辑决策，不负责剧本创作、演员身份识别、自动配乐、复杂转场或发布平台上传。
