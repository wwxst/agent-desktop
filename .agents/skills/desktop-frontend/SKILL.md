# 桌面端前端界面

本技能负责指导 `packages/client/src/**` 共享客户端和 `apps/desktop/src/renderer/**` 桌面入口的界面修改与视觉验收。它不定义另一套设计事实；开始工作前必须阅读 [`docs/desktop-ui.md`](../../../docs/desktop-ui.md)，具体尺寸、层级、状态和验收矩阵以该文档为唯一来源。

```text
English term                中文术语          介绍
Desktop Frontend            桌面端前端        实现 Agent Desktop 当前用户界面。
Renderer                    渲染层            承载 React 界面和用户交互。
Visual Verification         视觉验收          通过真实渲染确认界面质量。
```

## 适用范围

- 修改或审查桌面端的布局、排版、颜色、间距、组件外观和响应式行为。
- 调整 `Composer`、`AttachmentChip`、`AgentActivity`、`ArtifactCard` 或 `App` 中的界面结构。
- 根据真实窗口截图判断信息密度、交互层级、重叠、溢出或演示品感。

不使用本技能设计新的产品能力、会话模型、智能体行为、进程通信契约、运行时架构或通用组件库。

## 开始工作

1. 阅读根 `AGENTS.md`、[`docs/desktop-ui.md`](../../../docs/desktop-ui.md) 和直接相关的渲染层源码与测试。
2. 同时遵守 [`engineering-governance`](../engineering-governance/SKILL.md)；若修改依赖、workspace 或架构边界，按其导航继续阅读工程基线。
3. 明确本次要解决的可见问题、允许修改的渲染层范围和不新增的功能。
4. 若 DeepSeek Harness 本地源码与运行页面可用，可以用它核对空间关系和交互层级；不得迁移其插件、插槽、状态存储或运行时架构。

## 使用视觉参考

参考截图和第三方界面是视觉证据，不是功能规格。开始实现前按以下顺序处理：

1. 提取与当前问题直接相关的布局、层级、密度、间距和交互状态，不从截图中的控件推断产品能力。
2. 将提取出的视觉关系映射到本项目现有组件和真实业务行为；没有当前消费者的元素不能进入实现。
3. 明确列出本次吸收的视觉规则和不实现的截图元素。品牌、文案、选择器、模式、标签、附件类型和运行时概念均不能因为出现在参考图中而自动进入需求；当前侧栏不恢复独立顶部栏、Logo 或副标题，也不加入无真实行为的搜索、通知图标。
4. 若参考涉及空状态与输入区，必须同时验证无对话时的居中组合、产生内容后的底部停靠，以及切换时输入节点和草稿是否保持。

实现前和验收时分别维护一份“吸收项 / 禁止项”清单：截图中没有当前业务消费者的元素必须列入禁止项；发送按钮在空文本或处理中使用 `disabled`，但没有视频不应阻止有文字任务发送；禁用按钮使用默认指针，附件 `+` 也不出现额外蓝色焦点圈。

## 实施原则

- 继续维护现有业务组件，不为了视觉统一创建设计系统、`packages/ui`、供应商适配层或通用封装。
- 用户界面只展示和收集当前业务事实，不实现智能体核心逻辑，不改变执行追踪事件结构。
- 优先调整现有 JSX 和 CSS；没有明确收益时不新增依赖、主题系统或图标库。
- 空白必须来自可读宽度和层级控制，不能靠大面积占位制造“高级感”。
- 附件、工具活动和产物按业务语义呈现，避免把所有内容做成同一种带边框卡片。
- 不添加没有真实行为的按钮、菜单、状态、提示或未来功能入口。
- 保证固定格式控件尺寸稳定，长文件名、长任务、失败文本和多工具记录不能互相遮挡。

## 验证

完成代码修改后按风险执行：

```bash
corepack pnpm check
corepack pnpm desktop:build
corepack pnpm desktop:dev
```

`desktop:dev` 使用 Vite Dev Server（开发服务器）加载 Renderer（渲染层），修改 CSS 或 React 后窗口自动热更新；`desktop` 仅用于生产构建启动检查。

界面修改不能只用构建和测试判定通过。必须按 [`docs/desktop-ui.md`](../../../docs/desktop-ui.md) 的状态矩阵检查真实渲染，至少覆盖接近默认窗口的桌面尺寸；涉及响应式规则时再检查窄窗口。

视觉验收重点记录：

- 页面顶部是否出现无业务占位或额外装饰。
- 左侧品牌行是否保持纯文字层级、没有 Logo 或副标题；品牌行上下留白是否紧凑且与窄窗口一致。
- 空对话时欢迎内容与输入区是否形成居中整体，产生内容后输入区是否回到底部。
- 对话是否像智能体工作流，而不是论坛帖子或后台文档。
- 输入区空白、附件位置和按钮权重是否稳定。
- 空文本或处理中发送按钮是否禁用且使用默认指针，有文字但无视频时是否可发送，附件 `+` 是否没有蓝色焦点外圈。
- 5 至 10 个工具展开时是否保持紧凑且可扫描。
- 成功产物与失败状态是否清楚，但不过度卡片化。
- 是否存在文字溢出、控件位移、遮挡或无意义的大面积空白。

如果自动截图不可用，保持正确的 Electron 应用运行并明确记录人工验收范围；不要修改产品代码来迎合截图工具。

## 知识维护

- 已确认的视觉基线、状态矩阵和验收要求只更新 `docs/desktop-ui.md`。
- 组件职责或应用边界变化时更新 `docs/architecture.md`，工程流程变化时更新 `docs/engineering.md`。
- 本技能只维护执行顺序、范围限制和文档导航，不复制具体尺寸清单。
